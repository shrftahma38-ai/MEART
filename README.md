# پارچه‌سرای عرب‌زاده — فروشگاه اینترنتی پارچه

فروشگاه اینترنتی کامل و فارسی (RTL) برای فروش پارچه، با پنل مدیریت اختصاصی، سبد خرید و ثبت سفارش واقعی.

> این پروژه یک اپلیکیشن اجرایی است، نه نمونه نمایشی: محصولات، دسته‌بندی‌ها، قیمت‌ها، موجودی، سبد خرید،
> سفارش‌ها و مشتریان در PostgreSQL ذخیره می‌شوند و پس از بارگذاری مجدد صفحه باقی می‌مانند.

## معماری

| بخش | فناوری | مسیر |
| --- | --- | --- |
| کلاینت | React 18 + Vite + TypeScript + Tailwind CSS | `client/` |
| API | Express + Prisma | `server/src/` |
| پایگاه داده | PostgreSQL 16 | سرویس `db` در Compose |
| اجرای توسعه | `docker-compose.base44.yml` | ریشه پروژه |

ویترین (پورت ۳۰۰۰) درخواست‌های `/api` را به سرویس API پروکسی می‌کند؛ بنابراین احراز هویت با کوکی
`httpOnly` روی همان دامنه انجام می‌شود.

## اجرا

```bash
docker compose -f docker-compose.base44.yml up -d --build
```

* وب: `http://localhost:3000`
* سلامت API: `http://localhost:3000/api/health`
* پنل مدیریت: `/admin`

سرویس `api` پیش از بالا آمدن، `prisma db push` و اسکریپت seed را اجرا می‌کند. seed تکراری‌پذیر است و
داده‌های موجود (از جمله قیمت‌ها) را بازنویسی نمی‌کند.

## حساب مدیر

با مقادیر `ADMIN_EMAIL` و `ADMIN_PASSWORD` ساخته می‌شود. پیش‌فرض محیط توسعه (فایل
`.env.base44-defaults`):

```
admin@arabzadeh.ir / admin1234
```

برای محیط واقعی، این دو مقدار را (و `JWT_SECRET`) از داشبورد/متغیرهای محیطی تغییر دهید. دسترسی مدیریت
در سمت سرور با میدل‌ور `requireAdmin` بررسی می‌شود، نه فقط با پنهان کردن دکمه‌ها.

## محتوای اولیه

* ۷ دسته‌بندی: مانتویی، کت‌وشلواری، مجلسی، نخی، جین، پرده‌ای، مبلی
* ۳۶ محصول با تمام نام‌های درخواستی (مازراتی، باربی، کرپ، اسکاچی، فیونا، پرادا، شانتون، لینن، فاستونی،
  دیپلمات، گاباردین، کج‌راه، ساتن، حریر، گیپور، دانتل، ژاکارد، لمه، پولکی، کتان، تترون، چیت، متقال،
  ململ، وال، جین ساده/کشی/سنگ‌شور، هازان، مخمل، بلک‌اوت، شانل، جاسم …). نام‌های تکراری در همه
  دسته‌های مربوطه ثبت شده‌اند.
* **قیمت همه محصولات در ابتدا خالی است.** تا زمانی که مدیر قیمت را ثبت نکند، هیچ قیمتی نمایش داده
  نمی‌شود و دکمه خرید غیرفعال است.
* صفحات درباره ما، سؤالات متداول، راهنمای خرید، روش‌های ارسال، قوانین و حریم خصوصی با متن قابل ویرایش.

اطلاعات تماس فروشگاه (تلفن، نشانی، شبکه‌های اجتماعی) عمداً خالی است؛ از پنل مدیریت تکمیل می‌شود و تا
آن زمان در سایت نمایش داده نمی‌شود.

## قیمت‌ها و موجودی

* `Product.price` و `Product.salePrice` قابل خالی بودن هستند؛ `null` یعنی «قیمت ثبت نشده».
* قیمت فروش = `salePrice` در صورتی که کمتر از `price` باشد، در غیر این صورت `price`.
* تغییر قیمت از «محصولات» در پنل مدیریت، بلافاصله در صفحه اصلی، فروشگاه، صفحه محصول، سبد خرید و
  سفارش‌های جدید اعمال می‌شود.
* هر سفارش، قیمت و مقدار اقلام را در همان لحظه ذخیره می‌کند؛ تغییر قیمت بعدی، سفارش‌های قبلی را
  تغییر نمی‌دهد.
* قیمت و موجودی هنگام افزودن به سبد و هنگام ثبت سفارش دوباره در سرور اعتبارسنجی می‌شوند.

## پرداخت آنلاین

ساختار پرداخت آماده است اما هیچ پرداخت جعلی ثبت نمی‌شود. روش «پرداخت آنلاین» فقط زمانی به مشتری
نمایش داده می‌شود که درگاه واقعی تنظیم شده باشد:

```
PAYMENT_GATEWAY_URL=...
PAYMENT_GATEWAY_KEY=...
PUBLIC_BASE_URL=https://your-domain
```

بعد از ثبت این مقادیر، در تنظیمات فروشگاه گزینه «فعال بودن روش پرداخت آنلاین» را روشن کنید. وضعیت
پرداخت تنها بر اساس پاسخ درگاه (`/api/payment/callback`) تغییر می‌کند.

## تصاویر

تصاویر اولیه محصولات و دسته‌بندی‌ها در `client/public/media/` قرار دارند و از پنل مدیریت قابل جایگزینی
هستند (بارگذاری فایل یا ثبت آدرس تصویر). فایل‌های بارگذاری‌شده در `server/uploads/` ذخیره و زیر
`/api/uploads/...` سرو می‌شوند.

## ساختار پروژه

```
server/
  prisma/schema.prisma        مدل داده (کاربر، محصول، رنگ، تصویر، سبد، سفارش، تنظیمات، صفحه، پیام)
  prisma/seed.js              داده اولیه (تکراری‌پذیر)
  prisma/data/catalog.json    فهرست دسته‌بندی‌ها، محصولات، رنگ‌ها و تصاویر
  src/routes/                 auth، catalog، cart، orders، admin، payment
client/
  src/components/             چیدمان، UI، کارت محصول، بخش‌های صفحه اصلی، سفارش
  src/pages/                  فروشگاه، محصول، سبد، تسویه‌حساب، حساب کاربری، صفحات محتوایی
  src/pages/admin/            پنل مدیریت
```

## نکات استقرار

1. `docker-compose.base44.yml` یک محیط توسعه است (Vite dev server + `node --watch`). برای تولید،
   `client` را با `npm run build` بیلد و با یک سرور استاتیک/ریورس‌پروکسی سرو کنید و API را با
   `node src/index.js` اجرا کنید.
2. متغیرهای `DATABASE_URL`، `JWT_SECRET`، `ADMIN_EMAIL`، `ADMIN_PASSWORD` و در صورت نیاز درگاه پرداخت
   را در محیط واقعی مقداردهی کنید.
3. دامنه HTTPS را برای کوکی‌های `secure` در حالت `NODE_ENV=production` در نظر بگیرید.
